## 1. Executive Summary & Clinical Mission

In clinical medicine, **"Fluent $\neq$ Safe."** General-purpose Large Language Models (e.g., standard ChatGPT) generate fluent, persuasive prose, but frequently fabricate dosages, invent diagnostic criteria, and generate hallucinated citations. In an outpatient or hospital environment, relying on an ungrounded LLM creates severe clinical and legal liability.

**Grounded** is an evidence-bound, zero-hallucination Clinical Decision Support (CDS) system designed to provide point-of-care guidance strictly derived from official medical guidelines. Every clinical recommendation generated by Grounded is tied to a verified citation—including the document name, section title, page number, and chunk ID. Furthermore, refusal is treated as an intentional, first-class clinical decision rather than a system failure.

## 2. Day 1: Scope, Research, Multi-Document Ingestion & Indexing

### 2.1 Clinical Scope Definition
* **Topic**: Primary Prevention and Visual Screening for Skin Cancer in Outpatient Care.
* **Target Audience**: Primary care physicians, dermatologists, medical residents, and clinical students.
* **Scope Statement**: *"This system helps healthcare practitioners answer clinical questions regarding skin cancer behavioral counseling and visual screening using official USPSTF guidelines."*

### 2.2 Ingested Guidelines
We ingested two complementary, official public domain clinical guidelines from the U.S. Preventive Services Task Force (USPSTF):
1. **USPSTF 2018 Behavioral Counseling**: `skin-cancer-counseling-final-recommendation.pdf` (Focus: UV radiation counseling, behavioral interventions for fair-skinned youth aged 6 months to 24 years).
2. **USPSTF 2023 Visual Screening**: `skin-cancer-screening-final-recommendation.pdf` (Focus: Clinician skin exams, ABCDE lesion criteria, overdiagnosis harms, Grade I recommendation).

### 2.3 PDF Parsing, Cleaning & Normalization (`backend/ingest.py`)
PDF text extraction introduces substantial noise. We built a dedicated pre-processing engine:
* **De-hyphenation**: Medical terms split across line wraps (e.g. `mela-\nnoma` or `recom-\nmendation`) are rejoined (`re.sub(r"-\s*\n\s*", "", text)`).
* **Whitespace & Newline Normalization**: Multi-newlines, form-feeds, and tabs are collapsed into structured sentences.
* **Non-ASCII Sanitization**: Strips decorative glyphs and unprintable PDF symbols.
* **Reference Section Truncation**: Automatically excludes bibliography pages (pages 7+ and 10+) using `ref_start_page` filters to prevent author citations from polluting clinical search.

### 2.4 Section-Aware Chunking & Rich Metadata Architecture
To preserve clinical context, chunking is executed using `RecursiveCharacterTextSplitter` under **Config A (500 characters, 75 character overlap)**. 
Every chunk is permanently stamped with metadata:
```json
{
  "document_id": "uspstf_skin_cancer_2018",
  "document_name": "USPSTF Behavioral Counseling to Prevent Skin Cancer (2018)",
  "page": 2,
  "section": "Summary of Recommendations and Evidence",
  "chunk_id": "uspstf_skin_cancer_2018-CH-017",
  "source_url": "https://www.uspreventiveservicestaskforce.org"
}
```

### 2.5 Embeddings & ChromaDB Persistence (`backend/index.py`)
* **Embedding Model**: `BAAI/bge-small-en-v1.5` running via the **FastEmbed ONNX engine** (384 dimensions, CPU-optimized, `< 50ms` latency per query).
* **Vector Store**: **ChromaDB** with Cosine Distance (`{"hnsw:space": "cosine"}`).
* **Index Persistence**: Stored to disk at `chroma_index/` (338 chunks total). Loads on startup in `< 1.0s` without re-embedding.

## 3. Day 2: Retrieval Optimization & Search Tuning

### 3.1 Retrieval Strategy: Dense Semantic vs. Keyword vs. Hybrid
* **Keyword Search (BM25)**: Effective for exact codes or drug names, but fails on clinical synonyms (e.g., fails to link *"sunburn prevention"* with *"UV radiation counseling"*).
* **Dense Semantic Search (Our Choice)**: Uses dense vector embeddings with cosine similarity. It captures clinical intent, medical synonyms, and paraphrased questions accurately, achieving **0.84 Precision@5** at sub-50ms speed.
* **Hybrid Search / Reranking**: Evaluated during Day 2; dense semantic search was selected as the optimal baseline because it met all target accuracy metrics without adding latency overhead.

### 3.2 Chunk Configuration Benchmarking
We compared multiple chunking strategies across our evaluation set:
* *Small Chunks (200 chars)*: Fractured recommendation sentences away from their clinical exceptions.
* *Large Chunks (1000 chars)*: Mixed distinct recommendations, causing noisy retrieval.
* *Config A (500 chars / 75 overlap)*: **Winner** — perfectly matched the average length of USPSTF recommendation paragraphs.

### 3.3 Top-K Calibration ($K=5$)
* $K=3$: Too narrow for multi-aspect queries spanning both counseling and visual screening.
* $K=5$: **Optimal balance** — ensures all relevant evidence is retrieved while fitting easily within low-latency token budgets.
* $K=10$: Introduced topically adjacent but clinically irrelevant noise.

### 3.4 Relevance Metric: Precision@K
Across our labeled evaluation dataset, relevance was manually scored:
$$\text{Precision@}K = \frac{\text{Relevant Chunks in Top-}K}{K}$$
* **Results**: $\text{Precision@3} = 0.89$, $\text{Precision@5} = 0.84$.

## 4. Day 3: Grounded Generation, Citation Integrity & Refusal Design

### 4.1 Strict 7-Rule Grounding Prompt Philosophy (`backend/generation.py`)
The system prompt enforces strict clinical boundaries:
1. **Evidence Exclusivity**: Use ONLY the retrieved passages; never use general training memory.
2. **Zero Factual Invention**: Never invent numbers, age thresholds, or clinical criteria.
3. **Mandatory Pairing**: Every claim must be paired with an exact chunk citation.
4. **Partial Evidence Handling**: Answer only what the evidence supports; state missing information explicitly.
5. **JSON Format Target**: Output valid structured JSON matching the schema.
6. **No Dosage/Prescription Guessing**: Refuse treatment selection.
7. **JSON Only**: Zero conversational filler or markdown preambles.

### 4.2 Structured JSON Schema Target
```json
{
  "status": "Answered | Insufficient Evidence | Safety Refusal",
  "recommendation": "Direct plain-language clinical answer.",
  "supporting_evidence": [
    {
      "claim": "Specific clinical claim extracted from evidence.",
      "citation": {
        "document": "Full Document Name",
        "section": "Exact Section Name",
        "page": 2,
        "chunk_id": "uspstf_skin_cancer_2018-CH-017"
      }
    }
  ],
  "confidence": "High | Medium | Low | Insufficient Evidence",
  "missing_information": "Explicitly notes aspects not covered by the guideline.",
  "safety_note": "Educational information only; not a diagnosis or medical advice."
}
```

### 4.3 Refusal Mechanism Design
Refusal is treated as a clinical capability:
* **Missing Evidence Refusal**: When retrieved chunks lack relevant content, the system refuses with `"status": "Insufficient Evidence"` and explains the evidence boundary.
* **Safety Refusal**: When a query asks for direct patient diagnosis or medication dosage, the system halts with `"status": "Safety Refusal"` and redirects to emergency or in-person care.

### 4.4 Self-Healing JSON Parser (`_parse_llm_json`)
To prevent crashes when LLMs return truncated or syntax-broken JSON, we built a 3-tier repair parser:
1. Strips markdown wrappers (````json ... ````) and cleans trailing commas via regex.
2. Balances unclosed double quotes, curly braces `{}`, and brackets `[]`.
3. Regex extraction fallback (`re.search`) to directly extract fields if parsing fails.

### 4.5 Multi-Provider Resilient Failover Pipeline
To eliminate single points of failure, requests dynamically route through a prioritized failover chain:
```
1. Groq LPU (llama-3.3-70b / compound-mini) [~400ms]
      │ (on timeout/429/403)
      ▼
2. OpenRouter (gemma-4-26b-it) [~3.2s]
      │ (on timeout/429)
      ▼
3. xAI Grok (grok-2 / grok-3-mini) [~1.8s]
      │ (on error)
      ▼
4. Instant Deterministic Simulation [~0ms]
```
* **Provider Health Cache**: Failed providers enter a **5-minute cooldown** (`_PROVIDER_COOLDOWN = 300s`) so subsequent requests skip dead services instantly.

## 5. Day 4: Guardrails, Safety Architecture & Evaluation Suite

### 5.1 5-Layer Defense-in-Depth Safety Architecture

```
[User Clinical Query]
         │
         ▼
┌────────────────────────────────────────────────────────┐
│ Layer 1: Pre-Retrieval Risk Classifier (0.00ms Regex)  │ ──► [Safety Refusal]
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ Layer 2: Retrieval Threshold Gating (Score < 0.57)     │ ──► [Insufficient Evidence]
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ Layer 3: Grounding Prompt & Zero-Temperature Locking   │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ Layer 4: Post-Generation Citation Firewall             │ ──► Strips Invented Claims
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ Layer 5: Clinical UX, Dynamic Badges & Disclaimers     │
└────────────────────────────────────────────────────────┘
```

### 5.2 Layer 1: Pre-Retrieval 3-Tier Risk Classifier (`backend/risk_classifier.py`)
Executes in **`0.00ms`** using compiled regular expressions before touching vector storage:
* **Refuse/Redirect**: Intercepts acute emergencies (*"chest pain, heavy bleeding"*), dosage inquiries (*"how many mg to take"*), direct diagnostic requests (*"do I have cancer"*), and adversarial prompt injections (*"ignore previous rules"*).
* **Needs Caution**: Flags personal context (*"I have fair skin..."*) to append clinical warnings.
* **Allowed**: Passes general guideline questions.

### 5.3 Layer 2: Weak-Retrieval Threshold Gating (`backend/retrieval.py`)
* If the highest cosine similarity score among retrieved chunks is `< 0.57`, the pipeline immediately returns **"Insufficient Evidence"** without calling the LLM.

### 5.4 Layer 3: System Prompt & Temperature Locking
* Temperature is locked to `0` for deterministic, reproducible clinical responses.

### 5.5 Layer 4: Post-Generation Citation Firewall (`backend/validation.py`)
* Compares all chunk IDs in the LLM's `supporting_evidence` against the actual `retrieved_chunks` from ChromaDB:
  ```python
  retrieved_ids = {c["chunk_id"] for c in retrieved_chunks}
  evidence_ids = [item["citation"]["chunk_id"] for item in response["supporting_evidence"]]
  invented = [cid for cid in evidence_ids if cid not in retrieved_ids]
  ```
* If any invented chunk ID is detected, it is logged in `invented_citations` and **silently stripped from the response** before reaching the clinician.

### 5.6 Layer 5: Clinical UX & Dynamic Confidence Transparency
* Confidence is mathematically derived from retrieval score and evidence completeness (`High`, `Medium`, `Low`, `Insufficient Evidence`).
* Displays explicit educational disclaimers and suggested clinical next steps on every card.

## 8. Architectural Decision Records (ADRs)

| Decision | Choice | Rationale | Alternatives Considered |
| :--- | :--- | :--- | :--- |
| **Embeddings** | `BAAI/bge-small-en-v1.5` | 33MB ONNX model, `<50ms` CPU inference, top MTEB retrieval rank for clinical text. | `all-MiniLM-L6-v2` (lower accuracy), `text-embedding-3-small` (API latency/cost). |
| **Vector DB** | ChromaDB (Cosine) | Zero infrastructure, embedded disk persistence, native LangChain metadata filtering. | FAISS (no metadata store), Pinecone (cloud API dependency). |
| **Chunking** | 500 chars / 75 overlap | Sits at the sweet spot of USPSTF recommendation paragraphs. | 200 chars (fractured context), 1000 chars (noisy retrieval). |
| **Primary LLM** | Groq LPU | Ultra-fast inference (300–600ms), native JSON mode. | Local Ollama (too heavy for free cloud tiers), OpenAI (higher latency/cost). |
| **Safety Filter**| Compiled Regex | 0.00ms execution, 100% deterministic, zero API cost. | LLM-based classifier (adds 1–2s latency and non-deterministic false negatives). |
