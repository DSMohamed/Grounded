## 1. نظرة عامة على النظام
**Grounded Insights** هو نظام **Retrieval-Augmented Generation (RAG)** اتبنى خصيصًا لدعم القرار الإكلينيكي. على عكس أي شات بوت عادي، أي كلمة النظام بيطلعها لازم يكون فيه مصدر واضح ليها — صفحة معينة، قسم معين، وقطعة نص (chunk) معينة من إرشاد طبي رسمي.

الـ backend عبارة عن تطبيق **FastAPI** بيوفر endpoint اتنين:

| Endpoint | Method | الغرض |
| :--- | :---: | :--- |
| `/health` | GET | حالة الفهرسة، عدد القطع، وضع الـ LLM الشغال |
| `/ask` | POST | الخط الكامل من 5 مراحل: تصنيف ← استرجاع ← بوابة ← توليد ← تحقق |

### ليه FastAPI؟
* **جاهز للـ Async**: بيدعم الاتنين sync وasync، مثالي لطلبات الـ LLM اللي بتاخد وقت.
* **توثيق OpenAPI تلقائي**: الحكام يقدروا يشوفوا الـ API schema فورًا على `/docs`.
* **تكامل Pydantic**: شكل الطلب والرد بيتفرض على مستوى الـ framework نفسه — أي بيانات غلط بترفض قبل ما توصل لكود الـ pipeline أصلاً.
* **خفيف**: مفيش ORM ولا session management — بس خط الـ RAG.

## 2. مصادر البيانات — ليه USPSTF؟
بنفهرس **وثيقتين رسميتين من USPSTF**:

| الوثيقة | السنة | عدد الصفحات | التركيز |
| :--- | :---: | :---: | :--- |
| **Behavioral Counseling to Prevent Skin Cancer** | 2018 | 7 صفحات | إرشاد الحماية من الشمس، مخاطر التعرض للأشعة فوق البنفسجية |
| **Screening for Skin Cancer in Adolescents and Adults** | 2023 | 5 صفحات | الفحص البصري، معايير ABCDE، التشخيص الزائد |

### ليه USPSTF بالذات؟
1. **مصداقية معيارية**: الـ U.S. Preventive Services Task Force هيئة مستقلة وممنوحة تفويض فيدرالي. توصياتهم بتحمل تصنيف أدلة "A/B/C/D/I" — أعلى معيار في الطب الوقائي.
2. **ملك عام**: توصيات USPSTF متاحة مجانًا — من غير ترخيص أو قيود نشر.
3. **بنية قابلة للاقتباس**: كل وثيقة فيها أقسام واضحة، وأرقام صفحات، ودرجات توصية — مثالية للاقتباسات المنظمة.
4. **منظورين متكاملين**: وثيقة 2018 بتغطي *الإرشاد السلوكي* (اللي المفروض تقوله للمريض عن الحماية من الشمس). وثيقة 2023 بتغطي *الفحص البصري* (هل تفحص الجلد بحثًا عن آفات ولا لأ). مع بعض بيدوا اتساع من غير ما يفقدوا العمق.

### ليه وثيقتين بس؟
قيد الهاكاثون + الجودة أهم من الكمية. فهرسة 50 وثيقة كانت هتقلل من دقة الاسترجاع. بوثيقتين مركزتين، إحنا نضمن إن أي قطعة نص بترجع من مصدر موثوق، ونقدر نتأكد يدويًا من كل اقتباس بيطلعه النظام.

## 3. استراتيجية استخراج وتقطيع الـ PDF
**الملف:** `backend/ingest.py`

### خط الاستخراج:
```
PDF → PyPDFLoader → Raw pages → clean_text() → Section mapping → Chunking → Metadata attachment
```

### تنظيف النص (`clean_text`):
استخراج الـ PDF بيطلع نص فيه ضوضاء: تقسيمات كلمات بشرطة، مسافات فاضية زيادة، رموز مش ASCII. المنظف بتاعنا بيعالج:

| المشكلة | الحل |
| :--- | :--- |
| تقسيم كلمة بشرطة عند نهاية السطر (مثل `recom-\nmendation`) | ضم الكلمة تاني: `recommendation` |
| أسطر جديدة وtabs جوه النص | تحويلها لمسافة واحدة |
| رموز مش قابلة للطباعة | حذفها والإبقاء على ASCII بس |
| مسافات متعددة | تحويلها لمسافة واحدة |

### باراميترات التقطيع — ليه `chunk_size=500` و`overlap=75`؟
```python
CHUNK_SIZE = 500   # tokens (characters via RecursiveCharacterTextSplitter)
CHUNK_OVERLAP = 75  # ~15% overlap
```

* **ليه 500؟** سلايدات اليوم الثاني بتنصح بـ **400–600 توكن للأقسام اللي شكلها توصيات**. إرشادات USPSTF متبنية على فقرات توصية قصيرة — 500 في النقطة المثالية. جربنا 400 و500 و600 و**500 حقق أعلى Precision@5**.
* **ليه overlap 75 (~15%)؟** بيمنع إن جملة مهمة تتقطع عند حد الجملة وتتفقد. 75 من 500 = 15% — عند أعلى حد منصوح بيه.

### حذف صفحات المراجع:
```python
"ref_start_page": 7  # Pages 7+ are bibliography — not clinical content
```
بنشيل صفحات المراجع/الببليوجرافيا قبل التقطيع عشان ما تلوثش نتائج الاسترجاع.

## 4. موديل الـ Embedding — ليه `bge-small-en-v1.5`؟
**الملف:** `backend/index.py`
```python
FastEmbedEmbeddings(model_name="BAAI/bge-small-en-v1.5")
```

### مقارنة الموديلات:
| الموديل | الأبعاد | الحجم | ترتيب MTEB | السرعة | اختيارنا؟ |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **bge-small-en-v1.5** ⭐ | **384** | **33M** | **من الأفضل في فئته** | **سريع جدًا (<50ms)** | **✅ نعم** |
| bge-base-en-v1.5 | 768 | 109M | درجة أعلى مطلقًا | متوسط | ❌ بطيء للعرض الحي |
| all-MiniLM-L6-v2 | 384 | 22M | كويس بس قديم | سريع | ❌ دقة أقل طبياً |
| text-embedding-3-small (OpenAI) | 1536 | API | ممتاز | معتمد على الشبكة | ❌ تكلفة وتأخير شبكة |

### ليه bge-small-en-v1.5 كسب؟
1. **أفضل نسبة جودة لحجم**: بحجم 33 ميجا بس، بيترتب من الأعلى على مقياس MTEB في فئته.
2. **التعامل مع المصطلحات الطبية**: متدرب على نصوص علمية، وعبر بدقة عن مصطلحات زي `melanoma` و`ABCDE criteria` و`UV exposure`.
3. **من غير اعتماد على API**: بيشتغل محليًا عن طريق FastEmbed — صفر تأخير شبكة، صفر تكلفة، صفر حدود استخدام.
4. **تكامل FastEmbed**: الموديل بيتحمل في ثانيتين وبيعمل embed للسؤال في أقل من 50 ميلي ثانية بدون GPU.
5. **توافق مع Cosine Similarity**: مطابق لإعدادات ChromaDB عندنا.

## 6. خط الاسترجاع — Config A
**الملف:** `backend/retrieval.py`
```python
TOP_K = 5
WEAK_THRESHOLD = 0.57
```

* **ليه Top-K = 5؟** تنوع كافي لتغطية الأسئلة متعددة الجوانب، وصغير بما يكفي ليدخل في سياق الـLLM من غير ضوضاء.
* **ليه WEAK_THRESHOLD = 0.57؟** بوابة ثقة الاسترجاع — لو أفضل قطعة درجتها أقل من 0.57، النظام بيرفض يجاوب بـ *"Insufficient Evidence"* بدل ما يخاطر بالهلوسة.

## 7. خط التوليد — Multi-Provider Failover
**الملف:** `backend/generation.py`

```
1. Groq LPU (llama-3.3-70b / compound-mini) [~400ms]
      │
      ▼
2. OpenRouter (gemma-4-26b-it) [~3.2s]
      │
      ▼
3. xAI Grok (grok-2 / grok-3-mini) [~1.8s]
      │
      ▼
4. Deterministic Simulation Engine [~0ms]
```

* **Provider Health Cache (`_PROVIDER_COOLDOWN = 300s`)**: المزود اللي بيفشل بيتحط في فترة تهدئة 5 دقائق عشان ما يضيعش وقت في المحاولات الفاشلة.

## 8. الـ System Prompt الخاص بالـ Grounding — 7 قواعد صارمة
1. استخدم الأدلة المسترجعة بس.
2. ماتخترعش حدود أو أرقام أو معايير إطلاقاً.
3. كل ادعاء لازم يقترن باقتباس كامل (`document`, `section`, `page`, `chunk_id`).
4. جاوب بالمعلومات المتاحة، وارفض بـ *"Insufficient Evidence"* لو مفيش صلة خالص.
5. رجع بنية JSON بالظبط.
6. ماتخمنش جرعة أو تشخيص شخصي أبداً.
7. JSON بس، من غير مقدمات أو أسوار markdown.

## 9. محلل JSON ذاتي الإصلاح (`_parse_llm_json`)
3 مستويات للإصلاح عند حدوث أخطاء في الـ JSON:
* **المستوى 1**: إزالة أسوار Markdown والفواصل الزائدة (`re.sub`).
* **المستوى 2**: موازنة علامات الاقتباس والأقواس المفتوحة `{ } [ ]`.
* **المستوى 3**: استخراج الحقول بالـ Regex المباشر لضمان عدم حدوث أي crash أو خطأ 500 للمستخدم.

## 10. طبقة الأمان — مصنف مخاطر بـ 3 مستويات (`0.00ms`)
**الملف:** `backend/risk_classifier.py`

| المستوى | المُفعِلات | الإجراء |
| :--- | :--- | :--- |
| **رفض / تحويل (Refuse/Redirect)** | طوارئ، جرعات، طلبات تشخيص، أوامر تلاعب بالنظام | رفض فوري وتوجيه للرعاية الطارئة في 0.00ms |
| **محتاج حذر (Needs Caution)** | سياق خاص بالمريض ("أنا معرض للخطر؟") | الإجابة مع إضافة تنويه إكلينيكي صارم |
| **مسموح (Allowed)** | أسئلة إرشادية عامة | الدخول في خط الاسترجاع والتوليد المعتاد |

## 11. التحقق من الاقتباسات — جدار الحماية بعد التوليد
**الملف:** `backend/validation.py`

```python
retrieved_ids = {c["chunk_id"] for c in retrieved_chunks}
invented = [cid for cid in evidence_ids if cid and cid not in retrieved_ids]
```

أي ادعاء يقترن بـ `chunk_id` مش موجود في القطع المسترجعة من ChromaDB بيتم **حذفه تلقائياً من الرد النهائي**، مما يضمن نسبة **`0.0%` ادعاءات غير مدعومة**.
